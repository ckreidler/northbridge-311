Path B · Amazon Connect

Website → Connect flow → ACXD

Path A on the home page talks to ACXD Touchpoint directly. Path B is the contact-center shaped route: the website starts an Amazon Connect chat, Connect runs a flow, and that flow hands the conversation to ACXD.

When to use Path B

Use Path B when the demo should look like a real contact center: queue treatment, hours of operation, and escalation to a human agent all live in Amazon Connect. The browser uses @amazon-connect-touchpoint/web and a backend (or Lambda) that calls StartChatContact.

  1. The page requests a chat session from your backend.
  2. The backend calls Amazon Connect StartChatContact.
  3. Connect starts the inbound flow and can invoke ACXD.
  4. The widget on the page continues the conversation.

This repo does not ship Connect credentials, a StartChatContact proxy, or the Connect web SDK. Keep Path A as the nights-and-weekends demo; add Path B when you want the full website → Connect → ACXD story.
